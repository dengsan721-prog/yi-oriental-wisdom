# “艺｜东方人生智慧”全站五行主题与人生画卷改版设计规格

日期：2026-07-23

状态：用户已确认设计方向，待设计文档复核

目标分支：`feature/yi-content-engine-rebuild`

检查时基线提交：`319736c`

## 1. 本轮目标

本轮不是局部换色或单页文案修改，而是把现有产品统一成一套明亮、专业、易读、能持续使用的“东方人生智慧”体验：

1. 首页中央品牌字由“艺”改为隶书“命”，保留五层金色向外呼吸光环。
2. 全站以日主五行为主题依据，建立木、火、土、金、水五套明亮配色。
3. 结果页把测试人的姓名做成有仪式感的“本卷主人”展示。
4. “画像”升级为连贯、有情节、有画面的“人生画卷”，以《道德经》原文小注和原创通俗解读加深东方文化内核。
5. 只有“命盘”展示算命先生常说常用的专业命理术语。
6. “详批”不再作为独立模块；其中可执行的场景建议并入命盘。
7. “大运”紧跟命盘，用阶段故事而不是依据清单呈现。
8. “姓名”成为独立模块，提供五行齐备分、候选名输入和即时比较。
9. 合盘、镜像、传统保留民间共识与趣味表达，不再展示专业推导。
10. 人生首页变成真实数据看板，把“记录一件事”和“记录一个关系”放在第一优先级。
11. 提高信息密度和移动端可读性，减少无意义留白、重复入口和横向溢出。
12. 完成自动化验证、桌面与 390px 手机验收、GitHub Pages 发布和线上复验。

完成后的产品不能被称为“demo”。

## 2. 当前规格的优先级

本规格继承以下已落地规格和计划中的非冲突规则：

- `docs/superpowers/specs/2026-07-18-yi-content-engine-rebuild-design.md`
- `docs/superpowers/specs/2026-07-22-yi-name-and-chart-design.md`
- `docs/superpowers/plans/2026-07-22-yi-lishu-result-actions.md`

若这些文档与本规格在当前视觉、用户可见信息、导航、姓名评分或首页优先级上冲突，以本规格为准。

本规格覆盖此前与本轮确认冲突的产品决策，尤其包括：

- 首页中央主视觉字及产品内复用的小型标记由“艺”改为“命”。
- 视觉由深色墨曜金改为明亮的五行主题系统。
- 画像、姓名、大运、合盘、镜像、传统不再向用户展示专业依据、来源、可靠等级和使用边界章节。
- 姓名从命盘内部移出，成为独立结果模块。
- 姓名新增五行齐备互动分和候选名重算。
- “详批”从结果导航移除，场景建议归入命盘。
- 人生首页的事件和关系记录优先于月度、年度复盘。

本轮不自动修改“艺｜东方人生智慧”这一产品文字名称；用户明确确认的是主视觉单字由“艺”改为“命”。如以后需要产品重命名，应单独确认并处理页面标题、分享标题、仓库说明和搜索元数据。

此前规格中仍然有效且不冲突的工程约束继续保留，包括：

- 四柱与大运计算必须确定、可测试，不使用随机结果。
- 未知时辰、交节边界和资料不足不能生成伪精确结论。
- 出生地点不进入本机持久化、导出、URL 或分析日志。
- 姓名不得回写或修改原始四柱对象。
- 兼容汉字、IVS、PUA、多音字和简繁歧义继续按现有安全规则处理。
- GitHub Pages 必须完成真实线上验收，不能只以本地构建通过代替发布完成。

历史规格可以作为变更记录保留，但实现、测试、README 和当前验收文案不得继续把现行主视觉字称为“艺”或“中山篆”。产品文字名称中的“艺”不属于错误旧称。

## 3. 产品专业性的定义

专业感由四层共同构成，不等于满屏术语：

### 3.1 计算专业

- 底层四柱、十神、藏干、五行、关系和大运计算继续可追踪、可复核。
- 所有故事、镜像和建议都由确定的数据选择，不随机拼接。
- 对资料不完整的样本主动降级，不补造时柱和精确年份。

### 3.2 命盘专业

- 命盘采用成熟排盘软件常见的四柱表格和行业词汇。
- 只展示已经有完整算法和测试支持的专业字段。
- 不为制造“高深感”而硬凑格局、喜用神、神煞或吉凶断语。

### 3.3 内容专业

- 人生画卷使用编辑过的叙事结构，不使用 AI 式空话堆叠。
- 趣味表达要有分寸，不写土味段子、网络烂梗和廉价恐吓。
- 不把文化观察写成确定的人生承诺。
- 历史人物先说明是谁，再说明相似的选择和不相似的处境。

### 3.4 产品专业

- 全站使用一致的颜色令牌、间距、标题层级和交互反馈。
- 颜色只帮助识别和强调，不单独承担状态含义。
- 移动端关键触控高度不小于 44px。
- 长内容通过章节、短段落和稳定导航提高阅读效率，而不是依赖大量折叠。

## 4. 总体信息架构

### 4.1 主要产品路径

```text
启动页“命”
  → 出生资料
  → 结果生成
  → 人生画卷
  → 命盘
  → 大运
  → 姓名
  → 趣味扩展
  → 保存并进入人生首页
```

### 4.2 结果页主阅读链

结果页的一级阅读顺序固定为：

1. 人生画卷
2. 命盘
3. 大运
4. 姓名

结果页的次级趣味入口为：

1. 合盘
2. 镜像
3. 传统

“详批”不再出现在导航中。旧的 `#/report/detail` 访问应安全重定向到 `#/report/chart`，因为可执行内容已经并入命盘。

旧详批内容的迁移规则为：

- 自我、天赋、事业、财富、关系、家庭和节律中的可执行场景建议迁入命盘末尾。
- 适合连续人生叙事的优势、张力和选择迁入人生画卷。
- 专业依据、规则 ID、来源卡和重复边界说明不迁入用户可见页面。
- 没有新增信息的重复段落直接取消，不为维持旧条目数量而保留。

旧路由迁移必须使用历史替换而不是新增历史记录：

- `#/report/detail`、`#/report/detail/` 以及兼容解析后的旧详批深链统一 `replace` 为 `#/report/chart`。
- 浏览器后退不能再次掉入旧详批重定向循环。
- 直接刷新旧链接时，先完成现有档案／结果守卫，再进入命盘。
- 没有可用结果时继续走现有录入页守卫，不制造空命盘。
- 路由迁移不把姓名、出生资料或档案内容写入查询参数。
- 扫描导航、分享链接、测试、保存状态和当前文案中的 `detail`／“详批”引用；只有历史规格和明确的兼容测试可以保留。

为减少路由和历史链接的破坏：

- “人生画卷”可以继续复用内部 `portrait` 路由 ID，只更改用户可见名称。
- 命盘、大运、合盘、镜像、传统保留现有稳定 ID。
- 新增独立 `name` 路由 ID。
- 保存后的默认入口仍为人生首页。

### 4.3 导航呈现

桌面端：

- 主阅读链使用稳定的四项主导航。
- 合盘、镜像、传统放入“更多趣味”区域，但保持可直接访问和可复制 URL。

390px 手机端：

- 主导航不出现七八个等宽小按钮。
- 四项主导航采用可读的紧凑导航或两行布局，不能产生页面级横向滚动。
- 三个趣味入口以卡片或次级按钮呈现。
- 每个章节末尾提供“继续看下一章”，减少返回顶部换页的操作。

## 5. 全站五行主题系统

### 5.1 主题依据

排盘后，全站主题由 `professional.dayMaster.element` 决定：

- 木
- 火
- 土
- 金
- 水

以下情况使用中性主题：

- 尚未排盘。
- 日柱属于不确定柱。
- 主题值缺失或不合法。

主题不得按五行计数的最大项、最小项或“缺什么”决定。日主是主题身份，不代表吉凶、补益或喜用神。

### 5.2 视觉基调

所有主题共享：

- 暖玉白页面底色。
- 近白卡片表面。
- 墨灰主文字。
- 柔和灰褐辅助文字。
- 低对比细边界。
- 小面积温润金色仪式强调。

五行主题色方向：

| 日主 | 主色方向 | 视觉感受 | 禁止方式 |
|---|---|---|---|
| 木 | 松枝青、玉绿色 | 生长、舒展、稳健 | 荧光绿、大面积深绿 |
| 火 | 朱砂、陶红色 | 热度、行动、明快 | 高饱和纯红、满屏警示感 |
| 土 | 赭金、秋香色 | 承载、稳定、厚实 | 发灰泥色、低对比黄字 |
| 金 | 银灰、香槟色 | 清晰、秩序、利落 | 全灰无层级、浅灰正文 |
| 水 | 雾蓝、黛青色 | 流动、洞察、安静 | 深蓝黑底、冷色满屏 |

主题色只用于：

- 当前导航。
- 主按钮和焦点环。
- 进度条和关键数字。
- 姓名印记。
- 小面积背景柔光。
- 品牌字局部强调。

命盘中的五行语义色独立固定，不随当前日主主题替换。木永远是木的语义色，火永远是火的语义色。

### 5.3 设计令牌

全站共享一组语义令牌，而不是按页面散落硬编码颜色：

```css
--yi-bg;
--yi-surface;
--yi-surface-raised;
--yi-text;
--yi-text-muted;
--yi-accent;
--yi-accent-strong;
--yi-accent-soft;
--yi-gold;
--yi-line;
--yi-focus;
--yi-danger;
--yi-success;
```

主题通过根容器上的 `data-element="木|火|土|金|水|neutral"` 切换。所有页面，包括启动页、录入页、结果页、弹窗和人生首页，都消费同一套令牌。

### 5.4 对比度和动效

- 正文与背景达到 WCAG AA 对比要求。
- 辅助信息不能只靠颜色区分，必须有文字、图标或位置变化。
- 焦点环在五套主题和中性主题下都清晰。
- 主题切换不闪白、不整页重挂载、不丢失当前章节。
- 遵守 `prefers-reduced-motion`。

## 6. 隶书“命”品牌字

### 6.1 字形

首页中央字由“艺”改为“命”，字符为 U+547D。

交付必须采用设备无关方案：

1. 优先从允许随产品再发布的本地隶书字体中提取“命”字。
2. 转为审计过的内联 SVG 路径。
3. 页面运行时不请求第三方字体服务。
4. 手机和桌面渲染同一个 SVG。

若现有隶书源字体包含 U+547D 且许可证允许子集发布，可复用同一来源；否则必须选择新的合法来源。不得凭视觉相似手画后冒充某一书家字形。

### 6.2 字形审计

源码、构建产物和 `docs/fonts` 必须记录：

- 字体名称和版本。
- 官方来源 URL。
- 许可证名称和许可证副本。
- 原字体文件 SHA-256。
- 提取字符 U+547D。
- glyph ID 或提取记录。
- SVG 路径 SHA-256。
- 桌面和手机覆盖验证。

README 和测试统一称为“隶书‘命’字形”，不得继续称为“中山篆”。

### 6.3 五层呼吸光环

- 保留恰好五层金色光环。
- 光环从字形附近依次向外扩散。
- 完整周期约 5 秒。
- 不旋转、不闪烁、不遮挡字形。
- 五层有固定错峰。
- 减少动态效果时停止扩散，保留两层静态柔光。

人生首页和结果页的小型品牌标记复用同一 SVG，但关闭大型光环并使用独立尺寸规则。

## 7. 结果页姓名仪式区

结果页顶部形成清晰层级：

```text
品牌小标记
本卷主人
测试人姓名
元素色姓名印记
个人命运全景报告
本次采用的出生事实
保存并进入人生首页 / 修改出生资料
```

姓名展示要求：

- 姓名是顶部最醒目的个性化信息，但不大过品牌主标题。
- 姓名可以使用东方衬线字体和轻量印章边框，不使用难认的装饰字体。
- 姓名过长时换行，不截断。
- 姓名为空时显示“未填写姓名”，不伪造称呼。
- 元素色印记同时有文字或图形标签，不能只靠颜色表达。

结果操作区继续遵守已确认的交互：

- 标题区域不出现“保存到本机”和“修改出生资料”。
- 操作区位于出生事实条下方。
- 主按钮为“保存并进入人生首页”。
- 次按钮为“修改出生资料”。
- 保留保存确认弹窗、失败提示、现有保存逻辑和关闭弹窗后的键盘焦点恢复。
- 390px 下按钮纵向排列、全宽、无横向溢出。

## 9. 人生画卷

### 9.1 定位

“画像”用户可见名称改为“人生画卷”。它是报告第一章，也是最主要的付费感来源。

它回答：

- 这是一个怎样的人。
- 这一生通常靠什么打开局面。
- 事业、关系和婚姻中会出现怎样的剧情。
- 关键张力怎样推动人生转折。
- 更成熟的版本会走向哪里。

正文不能出现四柱、十神、日主、月令、旺衰、藏干、冲合刑害等命盘术语。

### 9.2 叙事结构

固定为七段：

1. **人生一句话**：18–36 个汉字，能独立分享和复述。
2. **开卷**：用一个具体生活画面说明“这是怎样的一生”。
3. **事业线**：怎样起势、怎样站稳、靠什么赢得位置。
4. **婚姻与关系线**：怎样靠近、怎样表达、冲突时怎样反应。
5. **命运转折线**：最容易遇到的关口、代价和转向。
6. **中后程**：成熟后怎样重新组织事业、关系与自我。
7. **收卷**：一句有力量但不绝对化的结尾，以及当下最值得做的一件事。

每一卷都要具备完整的故事动力：

```text
主人公当下的处境
  → 想得到或守住什么
  → 优势帮助他第一次打开局面
  → 同一个优势开始形成代价
  → 事业或关系出现冲突和低谷
  → 主人公作出不同于过去的选择
  → 局面发生转折
  → 形成更成熟的人生方法
```

总长度目标为 1600–2600 个汉字。每个章节由 2–4 个短段落组成，既要足够详细，也不能变成一个超长文本墙。

### 9.3 《道德经》小注

人生画卷不是把《道德经》当作命盘证据，而是把原典及传统注本中的人生智慧作为故事转折和章末回味。

每份画卷选择 2–4 条真正贴合本次故事主题的小注。用户可见结构为：

```text
《道德经》小注 · 第六十四章
千里之行，始于足下
现代通俗注解：真正改变人生的，往往不是某个惊天决定，
而是在人人看不见的时候，把第一步走稳，再把下一步接上。
```

可采用的首批母题：

| 章节 | 短句母题 | 适用故事位置 |
|---|---|---|
| 第八章 | 上善若水、利万物而不争 | 关系、服务、合作 |
| 第十五章 | 浊以静之徐清 | 混乱期、节奏、等待判断 |
| 第二十二章 | 曲则全 | 受挫、转弯、保存实力 |
| 第三十三章 | 自知者明、自胜者强 | 自我认识、真正的胜利 |
| 第四十章 | 反者道之动、弱者道之用 | 逆转、韧性、以柔破局 |
| 第六十三章 | 图难于其易、为大于其细 | 事业执行、拆解难题 |
| 第六十四章 | 千里之行，始于足下 | 长期主义、行动起点 |
| 第六十六章 | 善下之 | 领导、承载、关系位置 |
| 第七十六章 | 柔弱处上 | 适应变化、避免僵硬 |
| 第八十一章 | 为而不争 | 收卷、成事与放下争夺 |

原文以[中国哲学书电子化计划《道德经》正文](https://ctext.org/dao-de-jing/zh)为基础，传统注解优先参考该站收录的王弼《老子道德经注》，并用《老子道德经校释》核对章节和异文。现代通俗注解必须先吸收至少一条传统注解的核心意思，再结合本次人生故事重新写作；不能只贴一句原文后自行发挥。

实现时建立本地冻结的 `dao-note-corpus-v1`，不在运行时抓取网页：

```ts
type ReviewedDaoNote = {
  id: string;
  chapter: number;
  sourceTextTraditional: string;
  displayTextSimplified: string;
  traditionalCommentarySummary: string;
  modernStoryMeanings: string[];
  sourceEdition: string;
  sourceUrls: string[];
  verifiedAt: string;
  reviewer: string;
  checksum: string;
};
```

首版只收录逐条人工校对的短句。每条记录固定：

- 采用章节和底本文字。
- 原文繁体。
- 人工核对的简体显示文本，不使用运行时自动繁简转换。
- 王弼注或其他明确传统注本的内部摘要。
- 《老子道德经校释》的异文核对结果。
- 来源 URL、核对日期、复核角色和内容校验值。

页面只显示短句、章节号和现代通俗注解，不展示来源清单。

使用规则：

- 不把原文改造成五行、十神或具体命运的证明。
- 不随机抽取名句。
- 同一句在一份报告中只出现一次。
- 每条原文只摘取足以支撑阅读的短句，不整章复制。
- 现代通俗注解必须结合传统注解、本章人物处境、冲突和选择，不能写成通用鸡汤。
- 存在异文时采用固定底本并在内部记录，不在用户页面展开校勘争议。

### 9.4 叙事模型

新增一个面向视图的叙事模型，底层继续复用现有报告和解释条目：

```ts
type LifeScrollNarrative = {
  oneLineTheme: string;
  openingScene: string[];
  careerArc: string[];
  relationshipArc: string[];
  turningPointArc: string[];
  matureArc: string[];
  closingLine: string;
  actionNow: string;
  daoNotes: DaoNote[];
  animalInterlude: StoryMirror;
  historicalInterlude: StoryMirror;

  uncertaintyFlags: string[];
};

type StoryMirror = {
  name: string;
  introduction: string;
  matchingScene: string;
  difference: string;
  takeaway: string;
};

type DaoNote = {
  chapter: number;
  excerpt: string;
  plainCommentary: string;
  placement:
    | "opening"
    | "career"
    | "relationship"

    | "closing";
  internalSourceId: string;

```

`internalEvidenceIds` 和 `uncertaintyFlags` 只供选择、测试和维护使用，不直接渲染。

### 9.5 内容生成规则

- 优先复用现有 `lifeTheme`、核心优势、中心张力和当下课题。
- 从现有解释条目中按同一主题选择素材，不再固定机械拼接八张卡。
- 同一结论在不同段落只能出现一次。
- 每个抽象判断必须落到人物、地点、动作、对话或结果中的至少一种。
- 事业、婚姻和转折不能只是换标题复述同一句话。
- 每份画卷至少包含一次“优势带来机会，也带来代价”的反转。
- 每份画卷至少包含一次低谷或卡点、一次主动选择和一次局面变化。
- 起伏来自人物选择和现实场景，不能编造某年发财、离婚、患病或遭灾等具体事实。
- 《道德经》小注必须由当前叙事母题选择，并与前后故事形成转折或回响。
- 采用模板和规则组合，不在客户端临时调用生成式接口。
- 不同命盘样本必须产生可辨认的主题、场景和行动差异。

### 9.6 语言标准

推荐：

- “你更像靠一次次把局面做稳的人。”
- “别人还在讨论方向时，你往往已经开始收拾现场。”
- “真正的转折，不是突然走运，而是你不再替所有人承担后果。”

禁止：

- “你注定三十五岁飞黄腾达。”
- “此命大富大贵，婚姻必有一劫。”
- “宇宙能量将为你打开财富通道。”
- 连续堆叠“能量、磁场、天赋、使命、频率”等抽象名词。

## 10. 命盘

### 10.1 页面结构

命盘按以下顺序展示：

1. 专业四柱表。
2. 命局总论。
3. 月令与旺衰。
4. 五行气势与显隐。
5. 天干地支关系。
6. 五行缺失说明。
7. 详细通俗解读。
8. 事业、关系、生活节奏的场景建议。

### 10.2 专业四柱表

列为：

- 年柱
- 月柱
- 日柱
- 时柱

行至少包含现有算法已经支持或本轮完成验证后可支持的常用字段：

- 天干
- 地支
- 主星／十神
- 藏干
- 藏干十神
- 纳音
- 旺衰或十二长生

以下字段只有在建立完整算法、固定口径和 golden cases 后才能展示：

- 格局
- 喜用神
- 神煞
- 空亡
- 调候

如果本轮无法严谨实现，不以空卡、占位词或笼统断语冒充。

### 10.3 专业解读

专业部分可以使用算命先生常说常用的语言，例如：

- 日主
- 月令
- 得令、得地、得助
- 透干、通根
- 比劫、食伤、财星、官杀、印星
- 生、克、制、化
- 合、冲、刑、害
- 五行偏旺、偏弱、显、藏、缺

每组专业判断后紧跟一段通俗翻译，但通俗翻译不重复专业词。

### 10.4 五行缺失

命盘需要明确显示：

- 哪些元素在稳定柱中显现。
- 哪些只藏不透。
- 哪些在当前可确定四柱中未出现。
- 未知时柱可能影响哪些结果。

缺失说明不能直接等同于喜用神，也不能写成“缺什么一定补什么”。姓名模块的齐备互动分独立计算，不改变命盘的五行数量和专业判断。

### 10.5 详细通俗解读

专业命盘之后的通俗解释不能只是把术语换成同义词。它必须是一段有起伏的解释故事，并完整回答：

1. 这个结构在日常生活中通常怎样表现。
2. 优势最先在哪些场合帮助用户。
3. 优势过度使用后会付出什么代价。
4. 遇到压力、误解或竞争时，第一反应是什么。
5. 怎样从旧反应转到更成熟的做法。
6. 用户可以观察哪些现实信号来验证或修正这段理解。

通俗长解的每个小节都必须具备：

```text
现实处境
  → 出现机会
  → 原有优势推动局面
  → 优势过度使用形成代价
  → 卡点或低谷
  → 作出新的选择
  → 局面转折
  → 用户可以观察的现实信号
```

通俗长解目标为 1200–2000 个汉字，按自我、事业、关系、节奏四个小节组织。它必须有故事性，不得混入新的专业术语，也不得与人生画卷逐句重复。

### 10.6 场景建议

原“详批”中有价值的内容归入命盘末尾：

- 事业选择场景。
- 合作和表达场景。
- 婚姻与关系场景。
- 压力恢复场景。
- 决策节奏建议。

事业、关系和节奏三类必须细致展开，不能各用一句话带过。

每个建议故事采用：

```text
触发场景
  → 用户通常的第一反应
  → 当下看似有效的做法
  → 后续容易付出的代价
  → 可以改变局面的转折动作
  → 一段具体示例
  → 可观察的结果信号
```

每一类至少包含两个完整微故事，而不是把所有场景压进一段清单。篇幅和内容下限：

- **事业**：总计 500–850 个汉字；至少两个微故事，覆盖任务进入、协作冲突、机会选择和长期积累。
- **关系**：总计 500–850 个汉字；至少两个微故事，覆盖靠近方式、误会、争执、修复和边界。
- **节奏**：总计 420–700 个汉字；至少两个微故事，覆盖高效期、过载信号、暂停方式、重新启动和决策窗口。

建议要像一段短故事，让用户看到“过去怎样发生—为什么卡住—下一次可以怎样做”，但不虚构已经发生过的真实经历。不显示规则 ID、依据和来源。

## 11. 大运

### 11.1 位置

大运紧跟命盘，是主阅读链第三章。

### 11.2 呈现方式

保留真实起运、大运和流年计算，但用户可见内容改为阶段故事：

- 这一程的主题。
- 事业会遇到什么局面。
- 感情和家庭的主要课题。
- 顺风处在哪里。
- 最容易吃亏的地方。
- 这一阶段最值得做的三件事。

每个大运卡片显示必要的年龄和年份范围，但不展示九项专业依据、规则清单或可靠等级。

### 11.3 资料不足

- 性别缺失且计算依赖性别时，不生成确定起运方向。
- 出生时辰未知时，依赖时柱的内容不生成。
- 页面用一句自然语言解释缺少的事实，并允许用户返回补充资料。

## 12. 姓名互动

### 12.1 定位

姓名是独立结果模块，不再嵌在命盘里。它是简单、可玩、可比较的互动工具，不改写基础命盘。

### 12.2 五行齐备分

用户可见名称为“姓名五行齐备度”，主显示采用“覆盖 4/5 项”，旁边显示对应的“80/100”。计算上仍按 100 分制：

```text
木 20 + 火 20 + 土 20 + 金 20 + 水 20 = 100
```

计算对象是：

```text
稳定命盘中已经显现的五行
＋
当前姓名中已审校用字的五行归类
```

每覆盖一种元素得 20 分，未覆盖一种扣 20 分：

```ts
score = coveredElements.size * 20;
```

这个分数：

- 只表示五行覆盖的趣味结果。
- 不等于姓名吉凶。
- 不修改命盘的五行计数。
- 不参与大运、人生画卷或合盘计算。
- 不触发“必须改名”的结论。

分数旁边固定显示“只看五行覆盖，不是姓名好坏”。页面、分享文案和推荐字均不得出现“高分姓名”“满分好名”“吉名”或“改名加分改运”等说法。

当稳定命盘本身已经覆盖五行时，当前名和所有已审校候选名都会显示 5/5、100/100；产品必须如实说明“本盘五行已经齐备，候选名字不会提高覆盖项”，不得另外制造差异分。

姓名中存在未审校字、未确认多音字或字形歧义时，不把未知项按缺失扣分；显示“资料待确认，暂不评分”。

现有“姓名现实使用实测分”不再作为当前姓名页的第二个 100 分公开展示，避免两个总分混淆。其底层合同可以暂时保留供兼容和后续研究，但本轮主界面只显示一个“姓名五行齐备度”结果。

新增独立、版本化的 `name-element-coverage-v1` 合同。姓名用字归类只能来自人工审校表，记录采用字形、采用字义、元素归类、来源、复核角色、复核日期和规则版本。不得用 Unicode 部首、总笔画、拼音声母或来源不明的商业字库自动生成五行归类。

现有 15 个审校字不足以支撑公开互动。发布前的离线审校库必须：

- 覆盖产品全部推荐字。
- 每种元素都有足够的常用男女通用名字用字。
- 用至少 100 个常见完整姓名组成离线覆盖样本。
- 覆盖样本中至少 95% 可以完成字形、读音、字义和元素归类；其余样本必须正确进入“资料待确认”而不是胡乱评分。

### 12.3 推荐字

根据未覆盖元素展示经人工审校的常用名字用字：

- 每个元素提供有限、清晰的推荐字。
- 每个字显示读音和一句简短含义。
- 不自动拼装成完整姓名后宣称“高分好名”。
- 姓氏默认保留。
- 简繁、异体和多音关系继续沿用现有确认机制。

### 12.4 候选姓名试算

- 用户可以输入候选新名字。
- 输入后重新运行完整的字形、读音和审校检查。
- 显示“当前姓名”和“候选姓名”两张对比卡。
- 对比内容只保留姓名、齐备分、已覆盖元素、仍缺元素和推荐字。
- 快速连续输入时，旧异步结果不能覆盖新结果。
- 候选姓名默认只保存在当前页面状态，不写入本机档案。

### 12.5 空姓名

如果最初没有填写姓名：

- 姓名模块仍可打开。
- 页面先邀请用户输入一个现用名或候选名。
- 不把姓名改成结果生成的必填项。

## 13. 合盘、镜像与传统

### 13.1 共用原则

- 趣味优先，但不轻浮。
- 使用民间熟悉的说法，不展示专业推导。
- 每个结论必须落到相处或生活场景。
- 不出现匹配百分比和单一总分。
- 不把任何一方定性为“克人”“不旺伴侣”或“不适合结婚”。
- “民间常说”仍要在内部记录来源和采用口径，只是不在阅读页面展示来源章节。

### 13.2 合盘

内容顺序：

1. 你们更像哪一种搭档。
2. 最容易产生好感的地方。
3. 最容易误会的地方。
4. 发生争执时各自的第一反应。
5. 一句民间常说的关系比喻。
6. 三个可直接尝试的相处动作。

### 13.3 动物镜像

不再只显示动物名称和抽象映射，改为：

- 这种动物怎样寻找机会。
- 怎样保护领地和关系。
- 受压时会怎样反应。
- 与用户相似的具体生活场景。
- 最值得借鉴和最需要避免的一点。

### 13.4 历史人物

每张卡先回答“这个人是谁”，再讲：

- 他／她处在什么时代和局面。
- 做过什么关键选择。
- 哪种行动方式与用户相似。
- 哪种处境与用户完全不同。
- 可以借鉴什么，不能照搬什么。

不展示资料来源、可靠级和出生时间争议；这些只在内部维护数据中保留。

### 13.5 传统

保留生肖、民俗、面相、痣相、掌纹等现有文化入口时：

- 用“民间常说”“传统里常这样理解”的自然表达。
- 先说明用户怎样观察，再给趣味解释。
- 不出现来源章节和流派争论。
- 不采集、上传或识别人脸、照片、痣位和掌纹。

## 14. 人生首页

### 14.1 核心目标

首页不是命理报告的缩略版，而是用户长期记录生活的入口和真实成就看板。

### 14.2 第一屏

顶部显示：

- 当前阶段。
- 下一步行动。
- 已记录事件数。
- 已记录关系数。
- 已完成行动数／总行动数。
- 已点亮的真实里程碑。

第一优先级操作为两个同权大按钮：

1. 记录一件事
2. 记录一个关系

点击后直接进入对应短表单，不要求先理解月度或年度功能。

### 14.3 首页内容顺序

```text
姓名与当前主题
真实数据看板
记录一件事 / 记录一个关系
当前行动清单
最近的事件与关系摘要
月度复盘
年度复盘
隐私、导出与清除
```

### 14.4 导航

人生首页导航调整为：

1. 首页
2. 事件
3. 关系
4. 月度
5. 年度

### 14.5 真实成就

只展示可从本机数据推导的事实：

- 完成第一条记录。
- 记录三件重要事件。
- 添加第一段关系。
- 完成第一项行动。
- 完成一次月度复盘。
- 完成一次年度复盘。

不展示没有数据支持的连续打卡天数、虚构等级、伪造“最近添加”时间或命理成就分。

零记录时所有计数显示为 0，并以两个核心记录按钮代替空白图表。删除事件、关系或行动后，计数、完成比例和里程碑必须立即按剩余真实数据重新计算，不能保留已经失效的成就。

关系记录表补充简短类型选择：

- 伴侣
- 家人
- 朋友
- 同事
- 其他

## 15. 内容密度与排版

### 15.1 版面

- 减少大面积空白和重复卡片外壳。
- 主内容最大宽度以舒适中文阅读为准。
- 正文行高保持舒适，但章节间距不能大到破坏连续阅读。
- 重点段落使用短标题、引句和侧边强调，不用大量彩色标签。
- 同一层级的卡片只使用一种边框和阴影规则。

### 15.2 长内容

- 人生画卷以连续章节阅读为主，不把每个段落做成需要点击的折叠卡。
- 命盘专业表格默认可见，白话和建议紧随其后。
- 大运只需要选择当前阶段，不要求多层展开。
- 姓名候选输入与结果在同一页面完成。
- 趣味模块保持三步以内完成主要操作。

### 15.3 移动端

- 390px 下无页面级横向滚动。
- 专业命盘表允许组件内部受控滚动或紧凑列布局，但页面本身不能被撑宽。
- 所有表单控件和按钮至少 44px 高。
- 长姓名、长地名、长干支说明允许换行。
- 固定导航不能遮挡正文和按钮。

## 16. 数据、隐私与状态

- 五行主题由当前排盘结果派生，不新增持久化字段。
- 人生首页继续使用现有 `yi-life-profile-v1`，除非实现真实创建时间确实需要迁移。
- 本轮默认不新增创建时间，避免无必要的 schema 升级。
- 候选姓名、读音选择和字形确认默认不持久化。
- 出生地点继续在保存、导出和旧档迁移时清空。
- 损坏档案继续安全删除并返回可理解提示。
- 本机存储失败不能使页面崩溃。
- 主题切换、章节切换和候选姓名试算不能修改原始 `FourPillarsResult`。

## 17. 测试驱动实施要求

所有产品代码变更先写失败测试，再做最小实现。

### 17.1 品牌与主题

- 首页只出现隶书“命”主字，不再把“艺”作为当前品牌主字。
- SVG 覆盖 U+547D。
- 字形审计、许可证、SHA-256 和手机端设备无关渲染均有测试。
- 恰好五层光环、约 5 秒周期和 reduced-motion 状态有测试。
- 木、火、土、金、水和中性六种主题均可确定派生。
- 日柱不确定时回退中性主题。
- 主题令牌覆盖启动页、录入页、结果页、弹窗和人生首页。

### 17.2 结果导航与可见边界

- 主阅读链顺序为人生画卷、命盘、大运、姓名。
- 合盘、镜像、传统仍可通过路由访问。
- 旧 `detail` 路由重定向命盘。
- 姓名为独立路由，不再嵌在命盘。
- 结果正文除命盘外不渲染专业命理术语。
- 全部用户可见结果模块不渲染“专业依据”“本章来源”“本章依据与使用边界”“可靠级”等标签。
- 出生事实条和保存操作交互继续回归通过。

### 17.3 人生画卷

- 至少覆盖五个日主主题和未知时辰样本。
- 不同样本产生不同的一句话主题、事业线、关系列和转折线。
- 正文不含命盘术语和来源标签。
- 动物与历史人物都有介绍、相似场景、不同点和可借鉴内容。
- 每份画卷包含 2–4 条与故事主题匹配的《道德经》小注。
- 小注章节、原文短句、传统注解摘要和现代通俗注解存在，原文不被当作命盘计算依据。
- `dao-note-corpus-v1` 的底本、简体显示、来源、核对日期和校验值固定。
- 每份画卷具备处境、欲望、机会、代价、低谷、选择、转折和成熟回响。
- 缺失条目时安全降级，不因固定 `pick()` 抛错。
- 相同句子和相同结论不在多段重复。

### 17.4 命盘

- 四柱表的列和专业行完整。
- 未知时辰显示时柱未定。
- 稳定柱、藏干、十神、旺衰和关系保持现有 golden cases。
- 未完成验证的格局、喜用神和神煞不显示伪结果。
- 五行缺失说明与姓名分数不会回写命盘。
- 场景建议已经从详批迁入命盘。
- 通俗长解达到自我、事业、关系、节奏四个小节，不是术语同义改写。
- 事业、关系、节奏建议都包含触发、反应、代价、转折、示例和观察信号。
- 事业、关系、节奏各至少有两个完整微故事。

### 17.5 大运

- 命盘后紧接大运。
- 阶段故事、顺风处、吃力处和三项行动存在。
- 不显示专业依据和规则列表。
- 性别或时辰不足时按现有规则降级。

### 17.6 姓名

- 齐备元素 5 项时为 100 分。
- 每缺 1 项扣 20 分。
- 未审校字不按缺失扣分，而是停止评分。
- 当前名与候选名可以独立计算和并排比较。
- 快速输入不会发生陈旧异步结果覆盖。
- 字形、读音和简繁选择随候选姓名正确重置。
- 姓名分析不修改命盘和大运对象。
- 空姓名可以进入互动输入状态。

### 17.7 人生首页

- 事件和关系主操作排在月度、年度之前。
- 事件数、关系数和行动完成数来自真实档案。
- 成就徽章只在条件真实满足时出现。
- 关系类型可以选择并正确保存。
- 390px 下五项导航和主按钮无横向溢出。
- 保存、导出、清除和隐私回归继续通过。

### 17.8 内容黄金样本与人工编辑验收

结构测试不能代替内容质量验收。建立至少八个固定出生样本，覆盖：

- 五种不同日主。
- 已知时辰和未知时辰。
- 五行齐备和存在缺项。
- 不同事业、关系与节奏主线。

每个样本冻结人生画卷、命盘通俗长解和三类场景建议的编辑黄金稿。自动审计检查：

- 禁用术语和禁用断语。
- 章节长度和故事节点。
- 《道德经》小注的章节匹配和校验值。
- 跨模块重复句。
- 连续抽象名词和模板化开头。

人工编辑量表每项 0–2 分：

1. 是否有具体人物、动作和场景。
2. 冲突、代价和转折是否存在真实因果。
3. 不同命盘样本是否能一眼看出差异。
4. 故事是否有趣且不轻浮。
5. 《道德经》小注是否真正推进故事。
6. 人生画卷、命盘白话和场景建议是否各有职责、没有互相抄写。

总分低于 10/12 的样本不得进入发布。正式发布前至少完成一次全样本人工复核并记录日期和复核结论。
